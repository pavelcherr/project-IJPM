# OJ

Харнесс на openJiuwen 0.1.19. Получает каталог задач и бюджет токенов, отбрасывает невыполнимые задачи до запроса к модели, остальные решает в порядке выгоды и пишет `answer.txt` в каталог каждой сданной задачи.

Образ: `python:3.11.11-slim-bookworm`. Зависимости зафиксированы в `requirements.txt`: `cryptography==48.0.1`, `openjiuwen==0.1.19`, `catboost==1.2.10`. Ключ прокси в репозиторий не входит и при запуске не скачивается.

## Сборка

```bash
docker build -t hack:latest .
```

Сборка не ходит в сеть во время запуска контейнера. `cryptography` ставится только готовым колесом, без сборки из исходников.

## Запуск

Организаторы запускают контейнер так: корень только для чтения, каталог задач смонтирован в `/data/tasks` с правом записи, в окружении есть `LLM_BASE_URL` и `LLM_API_KEY`.

```bash
docker run --rm \
  --network hack-net \
  -e LLM_BASE_URL -e LLM_API_KEY \
  -e BUDGET \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --cpus 8 --memory 16g \
  --workdir /app --entrypoint python \
  hack:latest \
  /app/run_agent.py --tasks-dir /data/tasks
```

`BUDGET` — бюджет в выходных токенах. Если переменная не задана, берётся 100000. `TASKS` можно не передавать: путь задач задаётся флагом `--tasks-dir`.

После каждой сданной задачи в её каталоге появляется `answer.txt`. Для кода туда пишется слово `DONE`, исправленный источник остаётся в `mylib.py`. Если задана переменная `OUT`, туда же после каждой задачи дописывается строка jsonl. Ошибка записи `OUT` прогон не останавливает: зачётный файл — `answer.txt`.

Локально, на примерах из `tasks/`:

```bash
export LLM_BASE_URL="https://api.neuraldeep.ru/v1"
export LLM_API_KEY="..."
export BUDGET=100000
python run_agent.py --tasks-dir tasks
```

Каталог `tasks/` в образ не копируется. На проверке его подменяют набором организаторов.

## Модели

На каждом вызове модель выбирается заново.

| Тип | Модель |
| --- | --- |
| search, coding | `qwen3.8-27b-noreason` |
| math, data_analysis, неизвестный тип | `qwen3.8-27b` |

Если тесты кода не прошли, один повтор уходит на `qwen3.8-27b`. Модели `qwen3.6-35b-a3b` не используются. Локальных языковых моделей нет. CatBoost стоит только во втором проходе проверки математики и ответ не пишет.

Одновременно в полёте не больше 3 запросов: четвёртый запрос прокси этого тарифа отклоняет. При ответе 429 слот освобождается, пауза длится до времени из `Limit resets at` и не дольше 70 секунд, затем запрос повторяется, всего до 6 раз.

## Бюджет

Счёт одного ответа: `ceil(вход / 10) + выход`. Кеш не даёт скидки. Рассуждения, которые прокси уже включил в выходные токены, второй раз не прибавляются. Если поле рассуждений больше поля выхода, оба числа складываются: так рассуждения входят в расход, в каком бы поле они ни пришли.

До запросов каждая задача оценивается как `ceil(длина промпта / 3 / 10) + цена выхода типа`. Стартовая цена выхода: search 10, coding 60, math 120, data_analysis 230. Длина промпта — это инструкция и полный текст файлов задачи.

Из задач, чья оценка не больше 90% остатка, берётся та, у которой больше `награда / оценка`. Первые 4 задачи идут по одной. После каждой фактический выход этого типа усредняется с текущей ценой (`0.5 * факт + 0.5 * старая цена`), и оставшаяся очередь переоценивается. Дальше задачи идут параллельно, пока есть свободный слот. Задача, которая после пересчёта не влезает в остаток, остаётся без `answer.txt`.

## Невыполнимые задачи

Проверка идёт до первого запроса и не читает поле `check`. Неизвестный тип остаётся в очереди. Узнанная формулировка, которая не попала в правило, тоже остаётся в очереди.

- **data_analysis.** Файл `*.csv`, названный в тексте, должен лежать в каталоге. Если имя не названо, берётся csv, который уже есть. Пустой файл отбрасывается. Значение в кавычках должно встретиться в ячейке. Имена колонок из предложения не читаются.
- **search.** Проверка включается, когда в тексте есть каталог вида `kb/`. В нём должны быть `.md` или `.txt`. Искомое имя должно быть в имени файла или в тексте заметки, и слово ключа до двоеточия (`Born`, `City`, `Employer`) должно встречаться в условии. Если каталог в тексте не назван, задача остаётся модели.
- **math.** Нет ни одной цифры и ни одного числительного — задача отбрасывается. То же для явной запретной операции: деление или остаток на ноль, квадратный корень из отрицательного, логарифм нуля или отрицательного, факториал отрицательного, ноль в недопустимой степени. Второй проход — CatBoost (`math_classifier/model.cbm`). Если модель или библиотека недоступны, задача остаётся в очереди. Противоречие в сюжете сюда не входит.
- **coding.** Каждый `.py` из условия должен быть на диске. Живой импорт несуществующей библиотеки отбрасывает задачу. Утверждение теста из литералов и встроенных функций, которое уже ложно, тоже. Один и тот же вызов с теми же аргументами и двумя разными результатами отбрасывает задачу. Одиночный вызов библиотеки остаётся модели: функцию можно переписать. Синтаксическая ошибка в тесте отбрасывает задачу.

## Траектории

Консоль — короткая траектория прогона, без файловых логов. Библиотечные логи openJiuwen выключены: корень контейнера только для чтения.

Строки по ходу:

- `--- старт ---` — число задач, бюджет, наличие адреса и ключа. Сам ключ не печатается.
- `--- проверка ---` — сколько задач решаемые и нерешаемые, и причина каждой отброшенной.
- `--- очередь ---` — сколько задач пойдёт в модель.
- `запрос <id> -> <модель>` — вызов.
- `<id> <статус> счёт=<токены> остаток=<бюджет> ответ=<текст>` — итог задачи. `answer.txt` к этому моменту уже записан, если статус `solved-model`.
- `--- пересчёт после 4 задач ---` — новые цены выхода по типам.
- `--- итог ---` — баллы, расход, остаток, разбивка по типам.

Полная запись по задаче, включая токены входа, выхода и рассуждений, дописывается в `OUT`, когда эта переменная задана.
